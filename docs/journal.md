## Day 2 - Configuring My Linux System to Support building with Yocto
I spent today reconfiguring my partitions and creating a new partition of 250gb for my Yocto storage area. This took a fair amount of time as I have a dual booted system and I had to change back and fourth between the two systems to  make sure everything was partitioned how I wanted it to be. After I got the partition set up how I wanted it to be I realized I was going to need to readjust my development workflow. I dont spend much time at home on my desktop where I have linux installed so I realistically would not be able to build my project for testing very frequently. Therefore I decided to set up an ssh connection between my Linux pc and my macbook I take to school and work. In order to be able to connect via any network I used Tailscale to set up a tailnet with just my pc and my macbook. Now I am capable of building with my linux pc remotely using my macbook and I can just do all the coding on my mac and push the latest version to github when I am ready to build and test it.

### Conclusion
This was not what I was anticipating spending my development time on today but I ended up learning a lot about ssh and Tailscale which is a really cool tool. It solves a major problem I was concerned about in my development workflow.

## Day 3
This day was spent planning a more detailed idea of what I want the first MVP of Mine to look like. I would like to optimize mine for linux developers that also enjoy gaming via steam. Proton is already a tool integrated by steam to make linux gaming more reasonable however I still feel like it could be much better. I spent much of today looking through the linux kernel source code on github and researching the btrfs file system. I think I am going to implement btrfs as the root filesystem for Mine in order to try and better optimize storage. I am not sure yet if it will make a huge difference but using zstd to compress files with btrfs and utilizing the btrfs run time decompression to make this possible could help reduce the amount of storage taken up by each game. A common problem i run into while gaming is having to delete titles to donwload new ones only to redownload the deleted title a couple months later because i want to revisit it. If I could minimize the amount of times I have to do that Mine would already improve my quality of life as a linux user who games.

### Conclusion
btrfs is a very likely choice for the Mine root filesystem however I will need to test how impactful it is once I have some more legitimate builds of Mine available. Until then I will be stating btrfs as the root filesystem for Mine.
